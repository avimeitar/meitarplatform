# הפעלה ב-Railway

המדריך הזה מסביר איך מעלים את המערכת לאוויר ב-Railway ומתחברים בפעם הראשונה. אין צורך לכתוב קוד.

## מה רץ

- **שירות web אחד**: האתר והמערכת (Next.js). הוא נבנה מהריפו בגיטהאב בכל דחיפה לענף שמחובר ל-Railway.
- **מסד נתונים PostgreSQL**: כל הלידים, המשתמשים וההרשאות.
- בכל עלייה של השרת רצות אוטומטית עדכוני מבנה הנתונים (migrations), ונוצרים התפקידים והפרויקטים הבסיסיים אם הם חסרים.

## שלב 1: מסד נתונים

ב-Railway, בתוך הפרויקט: **New ← Database ← PostgreSQL**.

## שלב 2: משתנים בשירות ה-web

בשירות ה-web: **Variables ← New Variable**.

| משתנה | ערך |
|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (הפניה לשירות ה-PostgreSQL) |
| `BETTER_AUTH_SECRET` | מחרוזת אקראית ארוכה, לפחות 32 תווים. אפשר ליצור עם `openssl rand -base64 48` |
| `BETTER_AUTH_URL` | הכתובת של האתר, למשל `https://crm.meitargroup.co.il` |
| `BOOTSTRAP_ADMIN_NAME` | השם של מנהל המערכת הראשון, למשל אבי אבוטבול |
| `BOOTSTRAP_ADMIN_PHONE` | הנייד שלו, למשל 050-1234567 |
| `BOOTSTRAP_ADMIN_PASSWORD` | סיסמה זמנית לכניסה הראשונה (לפחות 8 תווים) |
| `ALLOW_CONSOLE_OTP` | `true`, רק עד שמחברים SMS או וואטסאפ (ראו שלב 5) |

**כתובת**: בשירות ה-web, **Settings ← Networking**. אפשר ליצור כתובת של Railway, או לחבר דומיין משלכם, למשל `crm.meitargroup.co.il`, עם רשומת CNAME אצל ספק הדומיין.

**הענף**: בשירות ה-web, **Settings ← Source**. כאן בוחרים מאיזה ענף בגיטהאב Railway בונה. כל דחיפה לענף הזה מעלה גרסה חדשה.

## שלב 3: כניסה ראשונה

1. אחרי שהפריסה מסתיימת, ביומן של השרת (**Deployments ← View logs**) מופיעה השורה `[bootstrap] created the first administrator`.
2. נכנסים לאתר עם הנייד והסיסמה הזמנית.
3. המערכת שולחת קוד בן 6 ספרות. **עד שמחברים SMS או וואטסאפ, הקוד מופיע ביומן של השרת**, בשורה שמתחילה ב-`[otp]`.
4. אחרי הכניסה: **החשבון שלי ← החלפת סיסמה**, ואז מוחקים ב-Railway את המשתנה `BOOTSTRAP_ADMIN_PASSWORD`.

## שלב 4: משתמשים והרשאות

- **משתמשים ← משתמש חדש**: שם, נייד ותפקיד. המערכת יוצרת קישור חד-פעמי לקביעת סיסמה (תקף ל-72 שעות). אם SMS מחובר, הקישור נשלח לבד; אחרת שולחים אותו בוואטסאפ מהמסך.
- **הרשאות**: מה כל תפקיד יכול לעשות. "מנהל מערכת" תמיד יכול הכול. אפשר לשנות את "מנהל מכירות" ו"סוכן", וליצור תפקידים חדשים.
- **השבתה** מנתקת את המשתמש מיד מכל המכשירים. **מחיקה** מבקשת קודם לבחור למי עוברים הלידים, המשימות והפגישות שלו.
- **יומן פעולות**: כל כניסה, קוד שנשלח, ניסיון כושל וכל שינוי במשתמשים ובהרשאות.

## שלב 5: חיבור SMS או וואטסאפ לקודי הכניסה

אפשר לחבר אחד מהשניים, או את שניהם (ואז כל משתמש בוחר איך לקבל את הקוד).

**SMS דרך Twilio**

| משתנה | ערך |
|---|---|
| `SMS_PROVIDER` | `twilio` |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` | מהחשבון ב-Twilio |
| `TWILIO_SMS_FROM` | מספר של Twilio, או שם שולח מאושר כמו `Meitar` |

**וואטסאפ דרך Meta (WhatsApp Cloud API)**

1. ב-Meta Business Manager יוצרים תבנית מסוג **Authentication** בעברית, עם כפתור "העתקת קוד", ומחכים לאישור.
2. משתנים:

| משתנה | ערך |
|---|---|
| `WHATSAPP_PROVIDER` | `meta` |
| `WHATSAPP_TOKEN` | טוקן קבוע (System User) עם הרשאת `whatsapp_business_messaging` |
| `WHATSAPP_PHONE_NUMBER_ID` | מזהה המספר העסקי |
| `WHATSAPP_OTP_TEMPLATE` | שם התבנית שאושרה |

אחרי שהקודים מגיעים לטלפון, **מוחקים את `ALLOW_CONSOLE_OTP`**.

## שלב 6: גיבויים

בשירות ה-PostgreSQL: **Backups**, ומפעילים גיבוי יומי.

## אבטחה בקצרה

- כל כניסה: טלפון וסיסמה, ואחריהם קוד חד-פעמי לנייד. הקוד תקף ל-5 דקות, עם 5 ניסיונות, ועם הגבלה על מספר הקודים בשעה.
- "לזכור את המכשיר" חוסך את הקוד ל-30 יום באותו מכשיר בלבד. ניתוק מכל המכשירים מבטל גם את זה.
- אין הרשמה עצמית: רק מנהל יכול לפתוח חשבון.
- סיסמאות נשמרות מוצפנות (scrypt), ואי אפשר לשחזר אותן, רק לקבוע חדשות.
- אף אחד לא יכול לתת הרשאה שאין לו, ותמיד נשאר לפחות מנהל מערכת פעיל אחד.

## פיתוח מקומי

```bash
npm install
cp .env.example .env   # ממלאים DATABASE_URL ו-BETTER_AUTH_SECRET
npx prisma migrate dev
npm run dev
```

נתוני דוגמה (רק למסד נתונים ריק): `npx tsx scripts/seed-demo.ts --yes`

בדיקות: `npm test`. בדיקות מול מסד נתונים: `TEST_DATABASE_URL=... npm test`.
